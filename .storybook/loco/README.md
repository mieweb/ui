# Loco i18n (Storybook only)

Storybook tooling for previewing and harvesting translations with
[Loco](https://loco.os.mieweb.org). None of this ships in the `@mieweb/ui`
package: nothing under `src/` imports it except the two demo stories.

| File | Purpose |
| --- | --- |
| `translator.ts` | `createLocoTranslator()` used by the self-translating demo stories. |
| `live-sync.ts` | Filters runtime-discovered phrases before the dev proxy posts them to Loco. |
| `static/i18n-translations.json` | Committed pack, generated by `pnpm loco:pack:sync` (ar, es, zh-Hans); served at `/i18n/`. |
| `static/loco.min.js` | Vendored Loco runtime 1.3.0 (unmodified) so package mode works offline. |

The **Loco i18n** toolbar in [`preview.tsx`](../preview.tsx) has three modes:

- **Disable** (default): stories render untouched; the runtime never loads.
- **Loco i18n** (package): translates from the committed pack.
- **Loco Sync Text** (live): dev server only, with `LOCO_API_KEY` in
  `.env.local`. The dev proxy in [`main.ts`](../main.ts) holds the key and only
  accepts same-origin requests on a loopback host. Live sync is for curated demo
  copy: form fields and editable regions are skipped, and stories must mark
  personal or clinical data `translate="no"`.

All three modes also apply to docs-only MDX pages such as the Introduction.

## Updating translations

Loco is the source of truth; don't hand-edit the committed pack.

1. Run Storybook with `LOCO_SERVER_URL` and `LOCO_API_KEY` in `.env.local`, choose
   **Loco Sync Text**, and open the stories or docs pages to harvest (in English).
   Their phrases appear as pending in the Loco dashboard.
2. Translate and **approve** them in Loco: only approved phrases are exported.
3. Run `pnpm loco:pack:sync` (same env vars) and commit the updated pack. The
   script keeps only `--languages=ar,es,zh-Hans`; pass `--languages=…` directly to
   `node scripts/sync-loco-pack.mjs` to export others.

Paragraphs with inline `<code>` should stay untranslated: `apply()` rebuilds them from
the translated template and drops the code.

## Runtime limitations

`static/loco.min.js` is vendored unmodified; these are Loco runtime behaviours to fix
upstream, with what this integration does meanwhile:

- **No read-only scan.** `rescan()` is the only scan, and once translations are loaded it
  writes stored originals back and re-applies them. Live sync therefore harvests only while
  no translations are loaded, and returning to English in live mode reloads the preview.
- **Mixed phrases drop non-inline children.** Phrases built around `<code>` and similar
  children lose them when translated, so live sync skips those phrases (and their slots).
- **Stale registry after English.** `apply()` writes its stored originals back and only
  rescans when none are still on the page, so text edited or rendered while English was
  showing can be translated from stale originals.
- **Late-mounted copies.** The mutation observer translates new copies of known phrases
  without recording them, so `restore()` leaves those copies translated.
- **`<option value>`.** Option values are translated (changing submitted values) and never
  restored.
- **Stale contexts.** Context caches are never cleared, so a heading changed in place can
  keep its old text as a context.
