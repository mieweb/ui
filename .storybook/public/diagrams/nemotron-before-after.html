Speaker diarization: before and after Nemotron

mieweb/ui#492. How a recorded visit becomes "Dr. Smith: … / Speaker 2: …", today and in the Phase 0 proof of concept. Both run entirely in the browser; audio never leaves the page.

  • Kept as-is
  • New
  • Removed from this path

Before: Whisper + TitaNet clustering legacy

VisitScribe → useVisitScribe → useDiarization → diarize.ts

Enrollment (once per person)

  1. VoiceSetup records phrase samples
  2. TitaNet embedding → centroid One vector per voice; sherpa-onnx WASM, main thread
  3. IndexedDB voiceprint store Scoped by voiceprintNamespace (PR #407)

Each recording (after Stop)

  1. Whisper turbo → text segments ~1.3 GB, Web Worker; assumes one speaker per segment
  2. TitaNet embed every segment Work grows with meeting length; segments < 1 s skipped and borrow a neighbour's speaker
  3. JS agglomerative clustering Cosine threshold 0.65, optional max speakers
  4. Match clusters to enrolled TitaNet voiceprints
  5. DiarizedSegment[] One speaker string per segment; labels only after Stop
  • Overlap: two voices in one segment → a mixed fingerprint → phantom or wrong speaker.
  • Interjections: "Tuesday" (0.5 s) is credited to whoever spoke before.
  • No live labels: clustering needs the whole clip.

After: Whisper + Nemotron with stored voiceprints Phase 0 POC

New experimental component (working name SpeakerScribe); legacy stays intact

Enrollment (once per person)

  1. Record a short voice sample
  2. Nemotron runs once → speaker-memory frames The "Nemotron voiceprint": up to ~33 frames × 512 values, stamped with the model revision
  3. IndexedDB voiceprint store Same namespace isolation; separate record type from TitaNet prints

Each recording

  1. Pre-fill Nemotron's speaker memory Lane 0 = Dr. Smith, lane 1 = Nurse… no audio replay
  2. Run in parallel

  4. DiarizedSegment[] + optional overlap fields Seeded lanes are already named; new voices stay "Speaker N"
  • Overlap is represented natively (two lanes lit at once).
  • Short interjections get their own lane; no 1 s minimum.
  • No per-segment TitaNet or clustering; live labels become possible (Phase 1).
