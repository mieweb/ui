# AI Design Agents

> **Beta** — the agent team is new and its commands and installed layout may
> still change. Expect rough edges; [tell us about them](#reporting-bad-guidance).

@mieweb/ui ships an installable **AI agent team** that teaches your coding
agent this design system: which component to pick, how to wire it, and the
house rules (theming, accessibility, RTL, Tailwind setup). Instead of your
agent guessing from source code, it works from the same curated guidance this
Storybook is built on.

## What you get

One agent to talk to — the **MIE UI Design Agent** — backed by a team of
specialists (catalog selection, forms, grids, theming, charts, migration, and
more). The orchestrator routes your request to the right specialist, so you
never have to know which one to ask. Editors with native agent support (VS
Code Copilot) show it in the agent picker; tools that only read `AGENTS.md`
get a roster in that file pointing at the same installed agents to read and
adopt as a persona.

## Install it in your project

From a project that already uses (or will use) @mieweb/ui:

```bash
npm install @mieweb/ui
npx mieweb-ui init-agent --experimental-agents
```

No install needed — you can also run it straight from the registry:

```bash
npx @mieweb/ui init-agent --experimental-agents
```

> Requires @mieweb/ui **0.12.1 or later**. While the team is in beta it is
> opt-in behind `--experimental-agents`; without the flag only the base
> instructions install.

### What lands in your repo

- `.github/agents/` — the MIE UI Design Agent and its specialist team
- `.github/skills/` — focused, on-demand knowledge (component APIs, theming,
  Tailwind integration, domain guides)
- `.github/instructions/` — always-on ground rules for the design system
- A managed block in your `AGENTS.md` pointing any agent (not just VS Code)
  at the above

Re-running `init-agent` after a package upgrade refreshes everything in
place. The refresh replaces managed files wholesale — the instructions file
and any agent or skill file carrying the managed marker — so don't edit
those directly. Files you created yourself (no marker) are never overwritten,
and in `AGENTS.md` everything outside the managed-block markers is preserved;
keep your customizations there or in your own files.

## Got a project zip from a web-based AI?

If a browser agent (ChatGPT and friends) built you an app with @mieweb/ui and
handed you a zip:

1. **Unzip it** and open the folder in your editor.
2. **Tell your local coding agent:** _"Install the dependencies and set up the
   MIE UI agent team"_ — well-behaved web agents seed the project's
   `AGENTS.md` with exactly those steps, so your agent will find them. If it
   doesn't, have it run `npx @mieweb/ui init-agent --experimental-agents`
   directly.
3. **Use the MIE UI Design Agent** — switch to it in your agent picker (or,
   in tools without one, have your agent adopt it from the installed
   `.github/agents/` files) and keep building.

## Using it without installing anything

Web-based agents (or quick one-off sessions) can use the hosted corpus
directly — point your agent at:

- [https://ui.mieweb.org/agent.md](https://ui.mieweb.org/agent.md) — the
  fetch-first entry point with routing to every skill and guide
- [https://ui.mieweb.org/llms.txt](https://ui.mieweb.org/llms.txt) — the
  standard llms.txt index of the same corpus

Agents that generate downloadable projects are asked to seed the scaffold's
`AGENTS.md` with the bootstrap steps above, so the project self-installs the
team the first time an IDE agent opens it.

## Reporting bad guidance

If an agent gives wrong or outdated design-system advice, that is a bug in
this package. Please
[open an issue](https://github.com/mieweb/ui/issues/new?labels=agent) with the
prompt, the answer you got, and what you expected — issues labeled `agent`
feed the team's eval suite.
