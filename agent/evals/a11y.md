# Evals — Accessibility

Primary agent: **MIE UI A11y Agent**. See [README.md](./README.md) for format
and scoring.

### A11Y-1 — Icon-only button name

- **Ask:** "Is `aria-label` enough for an icon-only button, or do I need
  visible text?"
- **Expect:** `aria-label` is sufficient but must be descriptive
  (`aria-label="Save"`, never "icon"/"button"); icon-only controls always
  need one; decorative icons get `aria-hidden="true"`.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (1); mieweb-ui.instructions.md — Rule 2

### A11Y-2 — Drag-and-drop keyboard support

- **Ask:** "My list reorders by drag-and-drop. Do I need keyboard support?"
- **Expect:** Yes — `useDragReorder` with `keyboard: true`, spread
  `rowProps(id)` on rows for Alt+↑/↓, and render visible `moveButtonProps`
  buttons as fallback.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (2), toolkit

### A11Y-3 — Modal focus restore

- **Ask:** "Modal traps focus and closes on Escape. Anything else?"
- **Expect:** Return focus to the trigger on close — the focus trap doesn't
  restore focus itself; track the trigger ref and focus it in `onOpenChange`
  when the next-open value is `false` (Modal has no `onClose` prop).
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (3), toolkit; src/components/Modal — `ModalProps`

### A11Y-4 — Announcement chattiness

- **Ask:** "Should a live region announce the item count on every keystroke?"
- **Expect:** No — announce meaningful changes only; debounce or scope to
  commits (e.g. reorders). `role="status"`/`aria-live="polite"` for passive
  updates, `role="alert"` for errors.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (4)

### A11Y-5 — White on primary-500

- **Ask:** "Does white text on `bg-primary-500` (BlueHive) pass AA?"
- **Expect:** No — 2.65:1, and it still fails at primary-700. Use
  `<Button variant="primary">` (AA-safe shade internally); never hardcode
  colors for button-like elements.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Known AA contrast traps

### A11Y-6 — Interactive element checklist

- **Ask:** "What makes an interactive element accessible here?"
- **Expect:** Accessible name (visible text, `aria-label`, or
  `aria-labelledby`), semantic HTML (no clickable divs), announced dynamic
  updates (Toast/Alert), logical tab order, focus indicators never removed.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 9

### A11Y-7 — Muted text trap

- **Ask:** "Is `text-neutral-500` on `bg-neutral-100` OK for small text?"
- **Expect:** No — 4.34:1 fails AA for small text; use `text-neutral-600`. In
  dark mode pair `dark:text-neutral-400` with a dark surface like
  `dark:bg-neutral-800`; verify per brand.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Known AA contrast traps

### A11Y-8 — Live announcements

- **Ask:** "How do I announce a state change to screen readers?"
- **Expect:** `const [announcement, announce] = useLiveAnnouncement()` and
  render `<div aria-live="polite" className="sr-only">{announcement}</div>`;
  call `announce()` on meaningful changes.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — toolkit

### A11Y-9 — Loading states

- **Ask:** "Custom CSS spinner for loading, or a component?"
- **Expect:** Library components only: `Spinner` (inline), `Skeleton`
  (placeholder), `LoadingPage` (full page). Never hand-roll.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 8

### A11Y-10 — Clickable div

- **Ask:** "My clickable div lacks `role=\"button\"` and `tabIndex`. Add
  them?"
- **Expect:** No — replace it with `Button` (or the right semantic
  component); don't bolt ARIA onto divs when a real component exists.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (2)

### A11Y-11 — Hidden file input

- **Ask:** "A hidden `<input type=\"file\">` sits behind a styled drop zone.
  Keyboard story?"
- **Expect:** It must stay keyboard-openable — wire keyboard handlers that
  trigger the input's `click()`, or use `DropzoneOverlay`/`FileManager`.
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Audit (2)

### A11Y-12 — Scrollable region

- **Ask:** "How do I make an overflow container keyboard-accessible?"
- **Expect:** `tabIndex={0}` + `role="region"` + `aria-label`, and it must be
  the single scroll container (no nested scrolling children).
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — toolkit

### A11Y-13 — Dark-mode hover contrast

- **Ask:** "Tab hover states look fine in light mode — do I need to check
  dark mode separately?"
- **Expect:** Yes — hover/active states must pass AA in **both** themes;
  dark-mode hover shades have regressed before (Tabs, outline Button). Use
  token pairs from the a11y checklist and verify per theme.
- **Agent:** MIE UI A11y Agent
- **Source:** issues #512, #511; agent/skills/mieweb-ui-a11y-checklist/SKILL.md — contrast traps

### A11Y-14 — Toasts and dynamic updates

- **Ask:** "Do async save results need announcing?"
- **Expect:** Yes — dynamic updates are announced via `Toast`/`Alert` (which
  carry live-region semantics), not silent inline text swaps.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 9

### A11Y-15 — Focus indicators

- **Ask:** "Can I remove the focus ring? The designer finds it ugly."
- **Expect:** No — focus indicators are never removed; restyle via tokens if
  needed, keep them visible (including in dark mode).
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 9

### A11Y-16 — Semantic landmarks

- **Ask:** "Is a div-based layout fine if the CSS is right?"
- **Expect:** No — use semantic HTML (`nav`, `main`, `button`, …); screen
  readers navigate by landmarks and roles, not by class names.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 9

### A11Y-17 — Exit animations

- **Ask:** "During an exit animation, the screen reader still reads the
  leaving element. Is that expected?"
- **Expect:** It happens today but isn't acceptable — exiting children must be
  `aria-hidden` and `inert` for the duration. `AnimatedPresence` does **not**
  yet do this automatically (open #474); hand-rolled exits must handle it
  themselves.
- **Agent:** MIE UI A11y Agent
- **Source:** issue #474 (open); agent/skills/mieweb-ui-a11y-checklist/SKILL.md — exit animations

### A11Y-18 — Icon-only Button pattern

- **Ask:** "What's the canonical icon-only button?"
- **Expect:** `<Button size="icon" aria-label="...">` — the `aria-label` is
  required, not optional.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 2

### A11Y-19 — Tab order

- **Ask:** "Does visual order vs DOM order matter for keyboard users?"
- **Expect:** Yes — tab order must be logical; don't reorder purely with CSS
  so that focus jumps around, and don't use positive `tabIndex` to patch it.
- **Agent:** MIE UI A11y Agent
- **Source:** mieweb-ui.instructions.md — Rule 9

### A11Y-20 — Verifying contrast per brand

- **Ask:** "Contrast passes on the default palette. Done?"
- **Expect:** No — brands redefine the primary scale, so brand-dependent
  pairs must be re-verified per brand (the checklist's traps are stated for
  the default palette/BlueHive).
- **Agent:** MIE UI A11y Agent
- **Source:** agent/skills/mieweb-ui-a11y-checklist/SKILL.md — Known AA contrast traps
