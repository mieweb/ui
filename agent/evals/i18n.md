# Evals — Internationalization / RTL

Primary agent: **MIE UI i18n Agent**. See [README.md](./README.md) for format
and scoring.

### I18N-1 — Hardcoded strings

- **Ask:** "I wrote `<Button>Save</Button>`. Is that OK?"
- **Expect:** No — every user-facing string goes through `t()`:
  `<Button>{t('common.save')}</Button>`. Includes aria-labels, placeholders,
  and error messages.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (1)

### I18N-2 — Missing keys ship silently

- **Ask:** "I added a locale bundle but missed some keys. Will anything
  break visibly?"
- **Expect:** No — missing keys silently fall back to `fallbackLng`, so they
  ship invisibly. Every bundle must cover every logical key of the canonical
  bundle in the same commit.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (2)

### I18N-3 — Auditing locale completeness

- **Ask:** "How do I check a locale bundle is complete?"
- **Expect:** Diff logical keys against the canonical bundle, stripping
  plural suffixes (`_one`, `_other`, …) before comparing.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (2)

### I18N-4 — Hardcoded locale in formatting

- **Ask:** "Is `date.toLocaleDateString('en-US', …)` fine?"
- **Expect:** No — that pins every user to en-US. Call it without a hardcoded
  tag, using the active language via `useLocale()` (where `LocaleProvider` is
  in scope) or `i18n.language`.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (3)

### I18N-5 — String concatenation

- **Ask:** "Can I build messages like `t('greeting') + name` or
  `` `${t('count')} items` ``?"
- **Expect:** No — concatenation breaks word order across languages. Use
  interpolation: `t('greeting', { name })`; `t('items', { count })` for
  plurals.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (3)

### I18N-6 — Plurals

- **Ask:** "How do I translate '3 items' vs '1 item'?"
- **Expect:** One logical key with `count` interpolation; bundles carry CLDR
  plural forms (`_one`, `_other`, …) — never an in-code
  `count === 1 ? … : …` branch.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (2), (3)

### I18N-7 — Physical margin classes

- **Ask:** "Does `className=\"ml-4\"` work in RTL?"
- **Expect:** No — use logical classes: `ms-4`, `ps-*`, `start-*`,
  `text-start`; never `ml-*`, `pl-*`, `left-*`, `right-*`, `text-left`.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist; mieweb-ui.instructions.md — Rule 10

### I18N-8 — Flipping icons

- **Ask:** "Do chevrons flip automatically in RTL?"
- **Expect:** No — add `rtl:-scale-x-100` to directional chevrons/arrows; do
  NOT flip decorative icons (checkmarks, media controls, up/down arrows).
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist

### I18N-9 — Arrow-key direction

- **Ask:** "My keyboard handler uses ArrowLeft/ArrowRight. RTL concern?"
- **Expect:** Yes — arrow keys follow **visual** direction: check
  `isRtl(event.currentTarget)` in the handler and swap the semantics.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist

### I18N-10 — isRtl vs useDirection

- **Ask:** "When `isRtl()` vs `useDirection(ref)`?"
- **Expect:** `isRtl()` is a one-shot snapshot for event handlers;
  `useDirection(ref)` is reactive, for when direction drives rendering. Never
  store an `isRtl` result across renders — it stales.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — direction toolkit

### I18N-11 — Portals and direction

- **Ask:** "How does a portaled Tooltip know the direction?"
- **Expect:** Portals escape local `dir` overrides — read direction from a
  non-portaled ref via `useDirection(ref)`, not from the portaled node.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist

### I18N-12 — Hardcoded BCP-47 tags

- **Ask:** "Can I pass `'en-US'` to `Intl.NumberFormat`?"
- **Expect:** No — drive Intl APIs from the active language, never hardcoded
  tags.
- **Agent:** MIE UI i18n Agent
- **Source:** mieweb-ui.instructions.md — Rule 10

### I18N-13 — Manual currency formatting

- **Ask:** "Is `'$' + amount.toFixed(2)` acceptable?"
- **Expect:** No — use `Intl.NumberFormat` with
  `{ style: 'currency', currency }` under the active locale; manual string
  formatting breaks symbols, separators, and placement.
- **Agent:** MIE UI i18n Agent
- **Source:** mieweb-ui.instructions.md — Rule 10; agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (3)

### I18N-14 — Adding a locale

- **Ask:** "What's the full procedure to add a new locale?"
- **Expect:** Add `<locale>.json` beside existing bundles covering every
  logical key with that locale's CLDR plural forms; register in i18next
  `resources`; expose in the language selector; on change call
  `i18n.changeLanguage(code)` and set `dir` via `isRtlLocale()`; verify Intl
  output.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Adding a locale

### I18N-15 — Physical inline styles

- **Ask:** "My inline styles use `marginLeft` and `textAlign: 'left'`. Caught
  by the class greps?"
- **Expect:** No — inline physical styles evade class greps and silently
  break RTL. Use `marginInlineStart`, `insetInlineStart`,
  `textAlign: 'start'`.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist

### I18N-16 — Key naming

- **Ask:** "Can I use the English text as the translation key?"
- **Expect:** Use logical keys (`common.save`), not English sentences —
  bundles are keyed by meaning, and plural/context suffixes attach to logical
  keys.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (1), (2)

### I18N-17 — Non-visible strings

- **Ask:** "Do aria-labels, placeholders, and toast messages need `t()` too?"
- **Expect:** Yes — every user-facing string, including assistive-tech-only
  text, placeholders, and error/notification messages.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Audit (1)

### I18N-18 — Setting dir on language change

- **Ask:** "The user switches to Arabic. What besides `changeLanguage`?"
- **Expect:** Set the document `dir` on every language change via
  `isRtlLocale()` — translations without `dir` leave the layout LTR.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — Adding a locale

### I18N-19 — RTL audit mechanics

- **Ask:** "How do I audit a codebase for RTL violations?"
- **Expect:** Grep for physical classes (`ml-`, `mr-`, `pl-`, `pr-`,
  `left-`, `right-`, `text-left`, `text-right`) **and** check what greps
  miss: inline physical styles, dynamic/conditional class strings, and
  directional keyboard handlers.
- **Agent:** MIE UI i18n Agent
- **Source:** agent/skills/mieweb-ui-i18n-checklist/SKILL.md — RTL checklist

### I18N-20 — Scope of Rule 10

- **Ask:** "What does the i18n rule actually require?"
- **Expect:** All user-facing text externalized through `t()`; dates,
  numbers, and currency via Intl under the active language; logical CSS
  properties/classes for RTL; no hardcoded locale tags.
- **Agent:** MIE UI i18n Agent
- **Source:** mieweb-ui.instructions.md — Rule 10
